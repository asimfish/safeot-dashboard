  • 结论：直控路线在平行夹爪 + xhigh 上已能完成"看图抓起并放到可见目标"（9/10）；在灵巧手上刚出现严格成功（3/10）。两者的主要失败都在接近阶段——手掌/指压向瓶体触发 −2 mm 穿透硬中止（E3 FR3 50 集里 18 集，全是 medium），不是抓取或放置本身。
  • 推理档位：单步抓取 medium = xhigh（E2 3/5 对 3/5），多步放置 medium 3/10 对 xhigh 9/10——任务越长档位差越大；medium 快 2.2–2.8×、token 少。规则：单步抓取可用 medium，放置/多步与灵巧手默认 xhigh。
  • 频率：Astra 不是高频策略。每次调用只给 1–2 个 waypoint（各 ≤2 s），仿真里 ≈0.5 Hz；因推理时物理暂停，墙钟上每 17–86 s 才一次决策，一集 85–640 s 里 84–99% 在等模型。真机上不能暂停，这个节奏就是实际节奏。
  • 对采集主线的影响：维持 cuRobo 脚本配方为正式采集主线；直控路线不导出 LeRobot 数据。Codex CLI（gpt-6-astra）作工程代理——从零搭装置、自查修 4 个装置缺陷、跑通 3 轮 85 个有效集——是这条线最可靠的收益。

1 系统接法：Astra 看什么、输出什么、谁在执行

回答"是不是把相机和 state 直接给 Astra、让它直接输出 action"：是，但 action 是末端 waypoint 而不是关节/力矩。每次决策把 4 张 640×480 RGB（detail=high）、一份本体状态 JSON 和一句任务描述放进一次 Responses API 请求，tool_choice 强制调用唯一函数 execute_motion（strict schema）。Astra 返回 1–2 个 waypoint：手部 link 的绝对世界坐标位姿（位置 + WXYZ 四元数）+ 夹爪开度（FR3）或 6 维手指关节目标（PsiBot）+ 时长。装置侧只有一个通用的实时 Jacobian DLS IK 伺服把 waypoint 变成 120 Hz 关节目标；没有任何规划器、避障、抓取点先验、技能或 action head。推理期间物理暂停，执行完再拍新图进入下一轮。这与 RoboCurve 原文"move_to waypoint 工具调用 → IK + 控制器"是同一形态。
每轮决策（一次 API 请求）： 输入 ┌ 4 × RGB 640×480（head / chest / third 固定 + wrist 腕相机；E1 只有前三路） ├ 本体状态 JSON：腕位姿、7 臂关节位置/速度/限位、夹爪开度或手指关节、相机 K/T、上一轮执行反馈、自己上一轮写的 memory、剩余请求数 └ 任务一句话 + 合同提示（单位、waypoint 约束、评估口径、"你的自报完成不算成功"） Astra ─► execute_motion(actions=[1–2 个 waypoint], task_done, visual_observation, memory_for_next_observation) 每个 waypoint = position_world_m[3] + quaternion_world_wxyz[4] + gripper_width_m（或 hand_joint_position_rad[6]）+ duration_s(0.25–2.0) 校验 ─► 位移 ≤0.15 m、转角 ≤0.6 rad（相对当前腕/前一 waypoint）、手指在限位内；任一不合法 → 整块拒绝、消耗预算、物理不推进 执行 ─► Jacobian DLS IK 伺服（固定增益 4，位置/四元数线性插值，后 30% 时长锁定终点；关节 slew ≤0.72 rad/s、手指按原生限速）→ Isaac Lab 电机目标 @120 Hz → 渲染 15 fps 评估 ─► 独立评估器只读物体真值（不回流模型）：抬升 ≥50 mm、末 1 s 质心差分速度 ≤50 mm/s、倾斜 ≤15°、无穿透硬中止；放置另加已释放 + 瓶底距圆垫中心 ≤4 cm

1.3 底层执行与评估（装置侧，三轮冻结不变）

  • 伺服：实时 Jacobian DLS（阻尼最小二乘）IK，固定关节修正增益 4；位置线性插值 + 四元数最短路径插值，每个 waypoint 后 30% 时长锁定终点；关节目标 slew ≤0.72 rad/s、手指按原生限速。物理步长 1/120 s，每 8 步渲染一帧（15 fps）。Phase 1 自检末端跟踪误差：FR3 0.09–0.10 mm / 2.4e-4 rad，PsiBot 1.7–2.5 mm / 0.006 rad。
  • 安全：GPU 接触张量监测"机器人 link 对非机器人物体"的穿透深度，−2 mm 即硬中止（每轮用 20 mm 受控探针验证监测器有效）。这是本线最主要的失败来源（见 2.3）。
  • 评估器：只读物体真值、绝不回流模型。抓取：抬升 ≥50 mm、末 1 s 内每 1/120 s 滑动的 4 tick（1/30 s）质心位置差分速度 ≤50 mm/s、倾斜 ≤15°、无硬中止。放置：另加已释放 + 瓶底距圆垫中心 ≤4 cm。E1/E2 曾用 PhysX 原生瞬时速度作保持门，E3 溯源后定为差分口径并透明重评（E2 FR3 6/10→9/10、PsiBot 0/10→1/10，原判分保留）。
  • 节奏：推理期间物理暂停；一次决策 = 拍图 → 请求（medium 15–19 s / xhigh 40–86 s）→ 执行 ≈3.3–3.8 s 仿真 → 再拍图。视频按 1× 仿真时间输出、不含推理等待。

3 判决与下一步

  • 条件正结果 FR3 平行夹爪：xhigh 放置 9/10 说明"看 4 路 RGB 对准可见目标并放下"在夹爪上成立；medium 抓取 60% / 放置 30%，差在接近安全裕度。下一步：接近阶段给两段式悬停–下降原语或让模型读到夹爪–瓶最近距离（不给抓取点），在 xhigh 上做 N=20 放置复验；仍不导出 LeRobot 数据。

2C.5 关键发现
  • 放置不是瓶颈，接近是：FR3 三个任务条件合计 50 集里 18 集在第 2–3 次请求就因接近时手掌/指压向瓶体（−2 mm）硬中止，全部是 medium（抓取 6/20、放置 11/20），xhigh 只有 1/10。而一旦抬起 ≥50 mm 且不掉网络，放置 15/15 成功。medium 的"快"（16.9–19.0 s vs 40.5 s）换来的是接近阶段的安全裕度不足。

  • 末端形态是决定性变量：同一模型、同一协议、同一物体，FR3 平行夹爪 6/10（若不计保持门的边缘失败，10 集里 9 集都抬起 ≥75 mm），PsiBot 6 维灵巧手 0/10。这与原文条件（夹爪 + 腕相机 + 高对比度物体 → block→bowl 19/20）方向一致，也解释了 E1 为何 0/5。
